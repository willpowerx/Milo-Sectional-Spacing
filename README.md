# Milo Sectional Spacing — Visual Reference

A design-engineering reference for the `.spacing-*` utility classes used in Milo sections. Each class applies responsive `padding-block` (top + bottom) to a page section using the S2A design token system.

Open `index.html` directly in a browser — no build step required.

## Changelog

### 2026-08-17 — Local patch: `--s2a-section-spacing-*` monotonicity fix

Not an upstream release — a local patch on top of `0.0.21`, applied ahead of a fix from the Consonant token team. Full rationale in `docs/audits/section-spacing-scale-fix-proposal-2026-08-17.md` (consonant repo).

- Root cause: every changed rung in the `0.0.21` `--s2a-section-spacing-*` output carried an inline `/** Milo-specific declarations */` comment — component-specific values needed by one Milo component were written directly into the shared scale, corrupting it for every other consumer, including this page.
- Reverted `-xl` / `-2xl` / `-3xl` / `-4xl` to distinct, ascending desktop values (the `0.0.20` baseline: 80/96/128/160), restoring full monotonicity at all three breakpoints — see the corrected scale table below.
- Also fixed a pre-existing issue while in here: Mobile `-md` (16px) sat below Mobile `-sm` (24px) even in `0.0.20`. Bumped to 24px — the one value here that isn't a straight revert, flagged in the proposal doc for sign-off.
- Added new standalone tokens `--s2a-section-spacing-pivot-{sm,md,lg}` in `s2a-tokens.css` carrying the three values removed from the base scale. None of this page's `.spacing-*` classes consume them — they exist here only because `s2a-tokens.css` mirrors the full token source — but they're documented in case a future component on this page needs the desktop-cap pattern.
- Replaced the ⚠ regression note in `index.html` with a "locally patched, pending upstream" note and updated the Token Source card.
- **This patch is not yet reflected upstream.** Once the Consonant team ships a real fix, re-sync from the published package and remove the local patch note.

### 2026-08-16 — Synced to `0.0.21`

- `s2a-tokens.css` brought from `0.0.20` to `0.0.21` (adds `--s2a-border-radius-6`, `--s2a-layout-none`, iconbutton token typo fix + light/dark border-token split, `--s2a-color-promo-cta-button-*`, and new `--s2a-hover-list-*` / `--s2a-side-by-side-*` / `--s2a-tab-side-padding` component tokens — none of which affect this page's `.spacing-*` classes).
- **⚠ Known upstream regression (superseded by the 2026-08-17 local patch above):** this page consumes `--s2a-section-spacing-*` directly (see the v0.0.20 migration entry below), so it inherited a non-monotonic scale from v0.0.21. The upstream `CHANGELOG.md` for 0.0.21 is self-flagged "auto-generated by the token release pipeline — verify before merge" and doesn't document this drift.

### 2026-08-14 — Synced to `0.0.20`, migrated onto official `--s2a-section-spacing-*`

- `s2a-tokens.css` brought from `0.0.17` to `0.0.20` (picks up the `0.0.18` `--s2a-spacing-128` primitive, the `0.0.19` border-radius refactor, and the `0.0.20` `--s2a-section-spacing-*` scale).
- `sectional-token-styles.css` no longer hand-rolls a 14-rung scale on top of `--s2a-viewport-vertical-padding-*`. That local extension has shipped upstream as the official `--s2a-section-spacing-*` tokens (v0.0.20), so `.spacing-*` classes now reference those directly. The redundant `:root` block re-declaring spacing/layout semantic aliases was also removed — `s2a-tokens.css` already provides them.
- One real value change from the migration: `.spacing-md` at Mobile now resolves to `--s2a-spacing-md` (16px), down from the local scale's `--s2a-spacing-xl` (32px). Every other rung was already an exact match with the official token.
- `.spacing-3xl` / `.spacing-4xl` values that route through `--s2a-layout-lg` move from 124px to 128px (the `0.0.18` primitive fix).

## Token architecture

Three-layer resolution chain:

```text
.spacing-sm
  └── padding-block: var(--s2a-section-spacing-sm)
        └── var(--s2a-spacing-lg)          ← mobile base
            var(--s2a-spacing-xl)          ← ≥1024px override
            var(--s2a-spacing-2xl)         ← ≥1280px override
              └── var(--s2a-spacing-24)    ← primitive
                    └── 24px
```

**Layer 1 — Primitives** (`s2a-tokens.css`): raw values like `--s2a-spacing-24: 24px`.

**Layer 2 — Semantic aliases** (`s2a-tokens.css`): human-readable names like `--s2a-spacing-lg: var(--s2a-spacing-24)`.

**Layer 3 — Responsive section-spacing tokens** (`s2a-tokens.css` + media queries): `--s2a-section-spacing-*` redefined at each breakpoint. This is the official package token as of v0.0.20 — `sectional-token-styles.css` no longer redeclares it locally.

Static classes skip layer 3 and reference semantic aliases directly.
